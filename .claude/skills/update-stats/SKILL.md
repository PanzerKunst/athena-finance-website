# Update the Results statistics

The "Results" section of the landing page (`src/UI/LandingPage/PerformanceStats/`, plus the "as of" date in
`LandingPage.tsx`) reads every figure from `src/Data/GeneratedStats.ts`. That file is generated by
`src/Data/StatsGenerator.ts` (`npm run generate-stats`) from the Bybit export sitting next to it. **Never edit
`GeneratedStats.ts` by hand, and never change `StatsGenerator.ts` as part of a routine update**. If the export
can't be processed, stop and report the problem.

Exports are named `Bybit-UTA-AllPerp-ClosedPosition-<start>-<end>.csv`, where `<start>` and `<end>` are Unix
timestamps in seconds.

## 1. Make sure exactly one export is in `src/Data/`

```sh
ls src/Data/*.csv
git status --short src/Data/
```

The generator reads the **first CSV in alphabetical order**. Because filenames start with the export's start
timestamp, an older export left in place sorts first and is used instead of the new one, with no error.

- **No CSV:** stop. Ask the user to drop the new Bybit closed P&L export (all perpetuals) into `src/Data/`.
- **One CSV:** continue.
- **Several CSVs:** keep the one with the largest `<end>` timestamp and remove the others:
  - A tracked older export (`git ls-files src/Data/*.csv`) can be removed with `git rm`. It stays in git
    history.
  - An **untracked** older export would be lost for good. Ask the user before deleting it.

## 2. Check that the export is actually newer

The first line of `src/Data/GeneratedStats.ts` names the CSV it was generated from. Compare that name with the
export found in step 1:

- **Same file:** the stats are already up to date. Say so and stop, unless the user explicitly asked for a
  rerun.
- **New export's `<end>` is older than the previous one's:** stop and confirm with the user. They probably
  dropped the wrong file.

Before regenerating, note the previous `statsAsOf`, `vol6months`, `vol30days`, and the last `cumulativePnl`
of `pnlStats6months` and `pnlStats30days`. You'll need them for the summary in step 5.

## 3. Regenerate

```sh
npm run generate-stats
```

The script prints the CSV it used, the number of closed positions, and the number of weekly and daily data
points. If it fails (for example, with a missing column or an unsupported timestamp format), Bybit probably
changed its export format. Report the exact error and stop. Don't patch the generator without the user's
go-ahead.

## 4. Sanity-check the output

Read the regenerated `src/Data/GeneratedStats.ts` and `git diff --stat src/Data/`. The output looks right when:

- **Header comment:** names the new CSV.
- **`statsAsOf`:** moved forward and isn't in the future.
- **`pnlStats6months`:** about 26–27 weekly points, the first `date` about 6 months before `statsAsOf`, all
  dates ascending with no gaps.
- **`pnlStats30days`:** at most 30 daily points, the last one on `statsAsOf`.
- **Pair lists:** `pnlPerPair6months` and `pnlPerPair30days` each hold up to 10 pairs, sorted from biggest
  profit to biggest loss.
- **Volumes:** `vol6months` and `vol30days` are positive, and `vol30days` < `vol6months`.

Then make sure the app still type-checks and lints:

```sh
npx tsc -b
npx eslint src/Data
```

Report any failures rather than working around them.

## 5. Summarise

Give the user a short before → after summary:

- **Date range:** the new export's range, and the `statsAsOf` date.
- **6 months:** net P&L (last `cumulativePnl`) and volume, each with its previous value.
- **30 days:** net P&L and volume, each with its previous value.
- **Pairs:** the top and bottom pair for each period.
- **Anomalies:** anything that looks off, such as a large swing in a single bucket or a new pair dominating.

Format dollars like the site does: `$12,345`, with negatives as `-$1,234`.

## 6. Commit (only if asked)

Commit only when the skill was invoked with `commit` (`/update-stats commit`) or the user asks for it. Stage
the export swap and the regenerated file together, so git records the CSV as a rename:

```sh
git add -A src/Data/
git status --short
```

Check that only `src/Data/` files are staged. Then commit with the repository's usual message, `Updated stats`.
Otherwise, leave the changes uncommitted and say they're ready to commit.
